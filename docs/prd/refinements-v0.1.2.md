## 1. 背景与目标

- 分类能力不一致：书签 / Skill 的标签可增删改，账号库与服务器的分组是固定种子、没有管理入口（本轮只统一分组，标签保持现状）；
- 侧栏标签区的搜索按钮与主内容区顶部全局搜索重复；
- 服务器新增未连接时卡片大面积空白；暂停 / 恢复的操作提示与页面头部重叠；
- 主密码设置失败提示过于笼统，无法指向真实原因（HTTP 非安全上下文）；
- Skill 安装（git clone）没有阶段反馈；
- 账号库顶部有重复的分组筛选条，卡片右上角操作常驻、平台 / 分组标签挤在标题行，且带有不需要的收藏功能。

目标：分组统一在设置页管理、模块内只做选择；修复上述界面问题。以上均已实施（实施记录见 §8）。

### 1.1 非目标

- 账号库「平台」不做实体化管理：platform 仍是账号行上的自由文本，侧栏平台筛选与色点颜色菜单保留；
- 标签删除语义不变：仍是级联删除标签关联，不删除条目；
- 分组不做拖拽排序；
- 上传压缩包的安装进度不改（只有 GitHub 安装展示阶段进度）；
- toast 全局位置不改（保持顶部居中，已确认）。

## 3. 分组统一管理

### 3.1 数据模型与迁移

**服务器分组（新增字典表）**

```sql
CREATE TABLE IF NOT EXISTS server_groups (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL UNIQUE,
  sort INTEGER NOT NULL DEFAULT 100
);
```

- `servers.group_name` 保持 TEXT，不改成外键：备份按名称导出、agent 协议、老库都零改动；
- 首次建表写入四个种子（家庭 / 公网 / 公司 / 归档），再把 `servers` 里出现过的其他分组名回填进字典；
- 重命名在单事务内 `UPDATE server_groups` + `UPDATE servers SET group_name = 新名`；
- 删除前 `COUNT(servers WHERE group_name = 名称)`，大于 0 直接 400。

**账号库分组**：沿用已有 `account_groups(id, name, sort)`，本轮补增删改接口与设置页界面；`accounts.group_id` 外键保持，删除前应用层计数拦截（SQLite 未开 `PRAGMA foreign_keys` 时 `ON DELETE SET NULL` 不生效）；重命名只改字典行，账号按 `group_id` 关联、无需级联更新。

**标签**：不改表，保持现状。

### 3.2 接口契约

**服务器分组**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/servers/groups` | `{ groups: [{ id, name, sort, count }], total }` |
| POST | `/api/servers/groups` | body `{ name }`；重名 400「分组「x」已存在」 |
| PATCH | `/api/servers/groups` | body `{ id, name }`；不存在 404，重名 400 |
| POST | `/api/servers/groups/delete` | body `{ id }`；非空 400「分组「x」下还有 N 台服务器，请先移出后再删除」；至少保留一个 |

`GET /api/servers` 的 `groups` 计数改为按字典输出全部名称（当前只输出白名单四项，动态分组会被静默丢弃）。

**账号库分组**

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/account-groups` | `{ groups: [{ id, name, sort, count }], total }`，需账号库已初始化（未初始化 409） |
| POST | `/api/account-groups` | body `{ name }` |
| PATCH | `/api/account-groups` | body `{ id, name }` |
| POST | `/api/account-groups/delete` | body `{ id }`；非空 400 |

### 3.3 交互规格

- 设置 → 分组（位于「导入」与「数据备份」之间）：两张卡片「账号库分组」「服务器分组」，列出分组名与数据条数，支持重命名、删除；底部输入框 + 「添加」新增（回车也可）；
- 删除非空分组提示数量并拒绝；至少保留一个分组；删除空分组二次确认，若服务器侧栏正筛选该分组则筛选回落为全部；
- 模块内只做选择：添加 / 编辑服务器与账号的分组字段是普通下拉，只列现有分组，并提示「分组在『设置 → 分组』里维护」；
- 服务器侧栏分组行只做筛选，保留色点颜色菜单（纯展示偏好）；账号库不再有分组筛选条（见 §4.5），平台筛选与色点颜色保留；
- 标签保持现状：侧栏编辑 / 颜色 / 置顶 / 删除，表单内输入创建；
- 侧栏第二区不再有搜索按钮，标签区只保留「更多」。

### 3.4 备份恢复兼容

- 服务器备份按分组名导出，恢复时遇到字典里没有的分组名自动建组，避免跨设备 / 旧备份 400；
- 账号库 `.slvault` 只认分组名，恢复同样按名称匹配，缺失时建组；
- 重命名 / 删除后旧备份恢复会多出空分组，属可接受行为；恢复结果的「新增分组数」通过 `groups_created` 回传，服务器恢复弹窗的预检 / 结果与账号库 `.slvault` 导入完成提示均会展示。

## 4. 界面问题修复

### 4.1 新增服务器后卡片空白 / 两行异常

**现象**：添加服务器后尚未连接时，卡片只剩「状态点 + 名称 + 分组」和「等待首次连接」两行，中间大片空白，看起来像渲染错误。

**根因**（`frontend/src/components/Server/ServerCard.tsx`）：`os_name` 为空时系统信息行仍带 padding，形成不可见空行；卡片固定 `min-h-[18.5rem]`，内容不足被强行拉高；页脚与占位文案重复「等待首次连接」。

**方案**（已实施）：无快照时不渲染系统信息行；用占位块填满卡片（图标 + 标题 + 说明 + 「查看接入指引 →」）；页脚 pending 改为「尚未回传数据」，paused 无快照显示「监控已暂停」占位。

### 4.2 暂停 / 恢复提示与页面头部重叠

**现象**：详情页点暂停 / 恢复，顶部 toast 盖住「返回服务器列表」与标题；徽章、提示条、toast 三处同时表达状态。

**方案**（已实施）：暂停 / 恢复不弹 toast，只更新按钮文案、状态徽章与提示条；toast 全局位置保持顶部居中（已确认不改右下角）。

### 4.3 主密码设置失败提示不清晰

**现象**：HTTP 访问下点「设置主密码并解锁」，只显示「设置主密码失败，请稍后重试」，无法关联到顶部的 HTTP 提示。

**根因**：`vaultStore.setupVault` 捕获异常后统一写死兜底文案，未区分「非安全上下文（`crypto.subtle` 不可用）」与「网络 / 服务端错误」。

**方案**（已实施）：

- 非安全上下文：顶部红色说明「当前为 HTTP 访问，浏览器禁用了加密 API，无法设置主密码。请改用 HTTPS 打开本页面后再试。」；两个输入与主按钮禁用，按钮文案改为「当前为 HTTP 访问，无法设置主密码」；不再额外重复一条错误文案（提示组件抽为 `SecureContextWarning`，登录页 / 锁定页与设置主密码处共用）；
- 其他失败：展示服务端具体 message + 重试，不再统一写「请稍后重试」；
- 未初始化时侧栏平台区显示「账号库尚未初始化」，不再展示历史平台。

### 4.4 Skill 安装（git clone）缺少进度

**现象**：点安装后只有按钮 spinner 与「安装中…」，大仓库克隆时长时间无反馈。

**根因**：`SkillsInstallController` 同步执行 clone，前端无阶段信息；git 本身不返回百分比。

**方案（已实施，方案 B：后端真实阶段）**：新增 `skill_install_tasks` 任务表，`POST /api/skills/install` 建任务后经 `exec` 异步拉起 worker（`utils/skill_install_worker.php`），立即返回 `{ task, task_id }`；前端轮询 `GET /api/skills/install/status?task-id=` 获取真实阶段。worker 依次写「连接仓库 → 克隆仓库 → 校验 SKILL.md → 写入 storage/skills」，前端展示阶段列表、不确定进度条与已用时长，失败停在失败阶段并展示错误摘要；进行中任务超时 10 分钟自动置 failed，同来源 / 同名并发任务 400。

### 4.5 账号库顶部移除分组筛选条

**现象**：账号库列表顶部有一排分组 chip（个人 / 工作 / 客户 / 归档），与侧栏平台筛选、设置页分组管理形成三个入口。

**根因**：`AccountVaultList` 顶部挂载 `AccountGroupFilter`（`frontend/src/components/Account/AccountGroupFilter.tsx`），分组筛选与平台筛选语义重叠。

**方案**（已实施）：移除顶部筛选条与 `group` URL 参数；分组只在「设置 → 分组」维护、在卡片上以标签展示。后端 `GET /api/accounts?group=` 参数保留（兼容 / 后续可复用），但界面不再有入口。

### 4.6 卡片右上角操作改为悬浮显示

**现象**：账号卡片右上角的「展开 + ⋯」按钮始终可见，观感上比预期更抢眼。

**根因**：`ModuleCardActions` 的按钮用 `.onhover-actions`（默认 45% 不透明度），按钮自带 `bg-background`，在浅色卡片上依然显眼。

**方案**（已实施）：改为 `.onhover-visible` 语义（0 → 100%），悬浮卡片、键盘聚焦、下拉展开时显现；触屏（`any-pointer: coarse`）常显。书签 / Skill / 账号三种卡片统一；`index.css` 注释与 `AGENTS.md` 同步更新。

### 4.7 卡片分类标签位置调整

- **账号卡片**：平台徽章从标题行右上角移到徽章行（与 2FA、授权、分组同排），标题行只留账号名；
- **服务器卡片**：分组徽章从头部右上角移到页脚状态行开头（`📁 家庭 · 在线`），头部只留状态点与名称。

理由：右上角只留给操作按钮；分类信息与其它元信息同排，扫读更顺，也避免长标题与徽章互相挤压。

### 4.8 移除账号库收藏功能

**现象**：账号卡片 / 详情页有星标与「收藏 / 取消收藏」菜单，账号库实际不需要收藏。

**方案（已实施）**：

- 前端：删除卡片与详情页星标、菜单项、`favorite` 类型字段与 `updateAccount({ favorite })` 调用；
- 后端：删除 `AccountPayload` 的 favorite 入参 / 出参、`Repository` 建表列与写入逻辑，`migrate()` 中 `DROP COLUMN favorite`；
- 备份：`.slvault` 导出不再写 `favorite`；导入旧文件时忽略该字段（未知字段不报错）。

**验收**：账号卡片 / 详情 / 菜单不再出现星标；`GET /api/accounts` 不含 `favorite`；旧备份仍可正常导入。

### 4.9 分页统计与左右控件同行对齐

**现象**：书签 / Skill / 账号库列表底部的「共 N 条项目」独占一行，位置比左侧「每页条数」与右侧页码控件高出一截，三块不在同一水平线上。

**方案（已实施）**：

- 宽屏（容器 ≥1024px）改为一行三栏：左「每页条数」、中「共 N 条」、右页码控件；中间项 `flex: 1` 撑满剩余宽度并居中，左右两侧 `flex-shrink: 0` 保持内容宽度贴边；
- 窄屏保持纵向堆叠居中，顺序为每页条数 → 共 N 条 → 页码；
- 三个模块共用同一 `Pagination` 组件，一处修改全部生效。

**验收**：宽屏下三块处于同一水平线且「共 N 条」严格居中；窄屏堆叠顺序与间距正常；亮色 / 暗色主题表现一致。
