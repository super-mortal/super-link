## 1. 背景与目标

### 1.1 侧栏

侧栏有两类问题。

**「全部」入口重复**：标签区 / 平台区顶部的独立「全部」行，与 O-12 确认的「再次点击已选标签 / 平台即取消筛选」重复；多占一行，也让取消筛选出现两个入口。服务器分组区没有这一行，三板块不一致。该决策已以 O-14 记录在 [optimization.md](optimization.md#L461-L482)。

**第二区实现分裂**：模块列表下方的标签 / 平台 / 分组由三套实现拼成——头部动作不同、搜索态高度不同（2.25rem vs 2rem）、行缩进不同（1.5rem vs 0.5rem）、计数字号不同（11px vs 12px）；标签行 hover 的三点比计数偏左；服务器模块图标生产用 `ServerCog`、原型用 `Server`。

### 1.2 界面细节

近期原型评审中确认的一批细节问题：

- 编辑书签表单先「网址」后「标题」，与录入习惯相反；
- 账号库平台侧栏的字母图标冗余；账号卡片头像可换成品牌 Logo；
- 原生 `select` 与 `datalist` 的系统弹层无法跟随主题，样式突兀；
- Skills 标签较少，不需要标签搜索入口；
- 服务器详情备注在添加时留空后无法补写；头部「运行时长」换行导致对齐错位；
- 卡片右上角操作按钮默认不可见，hover 时才出现且对比不足；
- 页面与弹窗右侧滚动条突兀；
- 模块行实心选中与筛选行实心选中同时出现，两块纯黑。

### 1.3 数据备份

备份能力分散且不完整：

| 板块 | 现状 |
| --- | --- |
| 书签 | `GET /api/export/data` → `POST /api/import/data`，整块书签 JSON |
| Skill | 只能单个导出 zip；没有整模块备份 |
| 账号库 | `.slvault` 加密备份，整库导出 / 导入 |
| 服务器 | **完全没有备份 / 恢复** |
| 设置 / 用户 | 不参与导出 |

目标是设置页统一入口，每个板块能单独导出、单独恢复。

### 1.4 目标

1. 书签 / Skill 标签区、账号库平台区不再渲染「全部」行；无选中即全部。
2. 第二区统一外壳：头部固定 2rem、动作位固定、搜索态同高，切换模块不跳动。
3. 标签 / 平台 / 分组共用同一套行几何、颜色点与计数规则。
4. 修正界面细节：表单顺序、品牌图标、全局下拉、Skills 搜索、备注编辑、头部对齐、悬浮按钮、滚动条、选中态。
5. 设置页新增「数据备份」分区，四板块独立导出 / 恢复。
6. 服务器备份包含配置 + Token 凭据；Skill 只备份 GitHub 来源并支持按地址重新拉取最新版本。

### 1.5 非目标

- 不改模块切换区（四个模块行 + 计数）。
- 不新增「未标记」入口，不改标签树结构、排序与「再次点击取消筛选」。
- 不新增平台 / 分组的编辑能力。
- 不改后端接口与数据模型（备份新增端点除外）。
- 不备份服务器历史指标、本地上传的 Skill、用户表与 `app_settings`。
- 不提供定时备份、云端备份、多版本快照。
- **本次不发布新版本**。

## 2. 侧栏优化

### 2.1 第二区统一外壳

| 区域 | 规格 |
| --- | --- |
| 外壳 | `side-sec`：头部 + 列表体，外包侧栏分区（上边框 + 0.5rem 上内边距） |
| 头部 | 固定 2rem 高；左侧分区标题；右侧动作区 |
| 动作位 | 固定顺序「搜索」「更多」，各 1.25rem；模块没有的动作渲染不可见占位，保持位置稳定 |
| 搜索态 | 输入框高度 2rem，替换头部，列表起始位置不变 |
| 列表体 | 行高 2rem，行间距 0.25rem，与模块列表一致 |

分区标题保留语义：书签「标签」、Skill「分类」、账号库「平台」、服务器「分组」。

### 2.2 行规格

| 元素 | 规格 |
| --- | --- |
| 行高 | 2rem |
| 左侧槽位 | 1.5rem（标签的 chevron 槽；平台 / 分组留空） |
| 颜色点 | 0.625rem 圆点，距名称 0.5rem |
| 名称 | 单行省略；父标签 500 字重 |
| 右侧计数 | 距右 0.25rem，11px，透明度 0.8，等宽数字 |
| 选中态 | 浅色底 + 主色文字，无左侧色条 |

标签树的父级与叶子标签名称对齐：chevron 槽固定 1.5rem；嵌套层级仍只缩进一级。

颜色点来源：

| 区域 | 颜色 |
| --- | --- |
| 书签 / Skill 标签 | 标签自身颜色（gray / green / red / yellow / aqua / black） |
| 账号库平台 | 平台品牌色（GitHub 深灰、Google 蓝、Microsoft 蓝、X 灰等） |
| 服务器分组 | 固定映射：家庭 绿、公网 蓝、公司 琥珀、归档 灰 |

平台 / 分组的颜色点只做视觉识别，不参与筛选逻辑。

计数与三点菜单：

- 默认显示计数；标签行 hover 时计数隐藏、右侧出现三点菜单。
- 三点按钮中心与计数中心对齐：右偏移 -0.25rem，不再偏左。
- 三点颜色使用 `--foreground`，比原侧栏前景更深。
- 点三点菜单中的「颜色」展开色板时，父级标签菜单必须保持打开，父容器不得裁剪子菜单。
- 平台 / 分组当前没有行级操作，暂不提供三点菜单；计数常显（待确认）。

### 2.3 移除「全部」入口（O-14）

| 区域 | 现状（生产 v0.1.0） | 目标 |
| --- | --- | --- |
| 书签 / Skill 标签区 | 顶部「全部」行（`SidebarAllRow`），显示模块总数，无筛选时高亮 | 不渲染 |
| 账号库平台区 | 顶部「全部」行（`Globe` 图标），显示账号总数 | 不渲染 |
| 服务器分组区 | 无「全部」行 | 保持现状 |

- 分区标题下方直接是标签树或平台列表；无选中时展示全部条目，侧栏无高亮项。
- 点击某项写入筛选并高亮；再次点击同一项取消筛选。
- 移动端点击后收起侧栏；取消筛选需重新打开侧栏。
- 锁定态点击平台统一 toast「请先解锁账号库」，不清除已有筛选、不写 URL。
- 计数、搜索、包含嵌套、显示项目数量、标签编辑 / 删除 / 置顶保持现状。
- 空态不额外补「全部」行。

### 2.4 服务器模块图标

- 生产端 `ModuleSwitcher` 使用 `ServerCog`（带齿轮）。
- 原型使用 `Server`（两层服务器机架）。
- 生产改用 `Server`，并清理 `ServerCog` 的 import。

## 4. 板块级备份与恢复

### 4.1 目标

1. 设置页「数据备份」分区，四张板块卡片各自导出 / 恢复。
2. 服务器支持配置 + Token 凭据备份，迁移后原 agent 可继续连接。
3. Skill 只备份 GitHub 来源：记录来源地址，恢复时重新拉取最新版本。
4. 恢复前预检，选择「合并」或「覆盖」，执行后逐条回报。
5. 书签备份只包含书签模块的标签与条目，不再混入 Skill 标签。

### 4.2 备份文件格式

所有 JSON 文件带 `module`、`version`、`exported_at`；文件名 `super-link-<module>-YYYYMMDD.json`。

**书签**：`tags`（仅 `module='bookmarks'`）+ `items`（含 `tag_ids`）；判重键 URL。

**Skill**：`skills: [{ name, source_url, description, fingerprint, installed_at }]` + `skipped.upload`；仅 `source_type='github'`；判重键 `name`；恢复调用现有 GitHub 安装流程拉最新版本；标签不在备份范围内。

**服务器**：`servers: [{ name, note, group, paused, token_hash, token_salt }]`；`group` 为分组名称（库内列名 `group_name`，分组是固定名称文本，没有 `group_id`）；不含历史指标；判重键 `name`；恢复保留 Token 哈希与盐，Hub 地址不变时 agent 无需重装。

**账号库**：沿用 `.slvault` 加密文件。

### 4.3 恢复流程

1. 点击「恢复」打开弹窗，选择文件。
2. JSON 解析并校验 `module`，展示预检：新增 / 同名 / 跳过；失败给出明确错误。
3. 选择「合并」或「覆盖」（默认合并）。
4. 执行恢复，展示逐条结果与成功 / 跳过 / 失败数。
5. 支持重新选文件；关闭弹窗即放弃。

边界：

- Skill 同名：无论合并还是覆盖，都按备份来源地址重新拉取最新版本；本地上传的 Skill 不受影响。
- 服务器合并：同名跳过；覆盖：同名按备份更新，并清空备份外的服务器。
- 书签覆盖：清空书签与书签标签后重建，Skill 标签不受影响。
- 空文件 / 缺字段 / 版本不兼容：预检阶段拦截，不写库。
- GitHub 不可达：Skill 恢复逐条失败，其他条目继续，结果标注原因。

### 4.4 安全

- 所有端点要求登录态；恢复为写操作，必须带 `X-CSRF-TOKEN`。
- 服务器备份含 Token 哈希与盐，等同凭据文件，UI 明确提示妥善保管；明文 Token 不可导出。
- 账号库备份始终为端到端密文；导入前浏览器校验主密码，失败不上传。
- 恢复结果只显示名称与状态，不写敏感字段到日志。

### 4.5 API 建议

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/backup/bookmarks` | 导出书签 JSON（替代现有 `/api/export/data`） |
| POST | `/api/backup/bookmarks/restore` | multipart：`file` + `mode=merge|overwrite` + `dry_run` |
| GET | `/api/backup/skills` | 导出 Skill 来源清单 |
| POST | `/api/backup/skills/restore` | 预检 / 恢复；逐条调用 GitHub 安装 |
| GET | `/api/backup/servers` | 导出服务器配置 + 凭据 |
| POST | `/api/backup/servers/restore` | 预检 / 恢复；保留 Token 哈希与盐 |
| GET | `/api/vault/export` | 账号库加密备份（现有） |
| POST | `/api/vault/import` | 账号库导入（现有） |

`dry_run=true` 返回扁平分类 `{ new, same, skipped, updated?, failed? }` 与逐条预览（`items`，另可带 `tags` / `note` / `removed`），不写库；执行响应为 `{ dry_run, mode, items, summary: { new, updated?, same, skipped, failed }, note?, removed?, tags? }`，逐条返回 `{ name, status, message? }`。旧 `/api/export/data`、`/api/import/data` 保留：旧导出已按 `module='bookmarks'` 过滤标签、不再混入 Skill 标签，旧导入对缺 `module` 的文件补默认 `bookmarks`；新端点缺 `module` 一律 400。
