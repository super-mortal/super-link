## 1. 背景与目标

### 1.1 背景

用户平时会有零散的待办事项，希望「想到就随手写下来」，写完能勾掉，从而获得完成的动力。现有的书签 / Skill / 账号库 / 服务器都是「已经存在的东西」，缺少一个记录「要做的事」的地方。外部待办工具（滴答清单、Microsoft To Do 等）要么需要联网账号，要么功能过重，与 super-link「数据完全自持」的定位不符。

### 1.2 目标

1. **零摩擦录入**：打开板块，光标已在输入框，写一行字回车即存，系统自动记录当前北京时间，不需要选日期、分组、优先级。
2. **完成有反馈**：勾选即完成，未完成区立刻变短、已完成计数增加；已完成收进底部折叠区，不干扰当前视线。
3. **一眼能找到**：列表按「今天 / 昨天 / 更早」分段，最新在上；支持按文字搜索（含已完成）。
4. **与现有产品一致**：沿用侧栏、暗色主题、语义色 token、卡片 / 列表视觉与响应式行为；侧栏位于「书签」下面。

### 1.3 非目标（首版不做）

- 截止日期、提醒通知（浏览器通知 / 邮件等）——已确认不做；
- 分组、标签、优先级、子任务清单——已确认不做，保持一行文字；
- 手动拖拽排序、置顶——未确认，列入候选 Q3；
- 多选批量操作、表格布局——首版不做，保持轻量；
- 编辑待办文字——已确认不做，记错了删除重写；
- 备份与恢复（第五板块）——已确认不做（T9），待办数据不在现有四板块备份范围内；
- 重复任务（每天 / 每周）、自然语言解析日期——不做；
- 多人协作、共享清单——不做（沿用单用户假设）。

## 2. 用户与典型场景

| 场景 | 描述 | 关键能力 |
| --- | --- | --- |
| 随手记 | 正在做别的事，突然想起一件要做的事 | 常驻快速输入框，回车即存，自动记录时间 |
| 每日清点 | 早上打开看今天要做什么 | 「今天」分段置顶、最新在上、未完成计数 |
| 勾掉完成 | 做完一件事，划掉它 | 圆形勾选框，勾选后进入已完成折叠区 |
| 回头找 | 想起上周记过一件事，想确认是否做完 | 搜索文字，跨未完成与已完成 |
| 清理积压 | 已完成区堆了很多，想清空 | 「清除已完成」二次确认后批量删除 |
| 记错了 | 写的时候太急，想改措辞 | 删除重写（单条删除二次确认），首版不支持编辑 |
| 只看一类 | 只想处理未完成的，或回顾已完成的 | 侧栏「未完成 / 已完成」点击筛选，再点取消 |

## 3. 术语

- **待办（Todo）**：一条只有文字与完成状态的事项，创建时间由系统自动记录。
- **未完成区**：内容区上半部分，按创建时间新→旧排列，列表布局下再按日期分段。
- **已完成区**：内容区底部可折叠区域，收纳已勾选的待办，按完成时间新→旧排列。
- **快速输入**：内容区顶部常驻的单行输入框，回车提交，提交后保持焦点可连续录入。
- **日期分段**：列表布局下的「今天 / 昨天 / 更早」三个小标题，按创建时间的日期部分（服务器时区，北京时间）划分。
- **侧栏筛选**：侧栏第二区「未完成 / 已完成」两行，点击只看该集合（行高亮），再点一次取消。

## 5. 功能需求

### 5.1 模块与入口

- 待办作为**普通模块**进入模块注册表 `lib/modules.ts`（与书签 / Skill 同级），`store.module = 'todos'` 切换，路由仍为 `/`（与书签 / Skill 一致，不做独立路由）。
- 侧栏位置：`MODULE_KEYS` 顺序改为 `['bookmarks', 'todos', 'skills', 'accounts']`，即「书签」下面；服务器仍是注册表之外的独立行，排在最后。
- 侧栏图标：`lucide-react` 的 `ListTodo`。
- 侧栏徽章：显示**未完成数**（不是总数），勾选完成后数字减少；0 时仍显示 0。
- 侧栏第二区（书签是标签区、账号库是平台区）：待办下显示**可点击的概览筛选**，两行「未完成 N」「已完成 N」；点击只看该集合（行高亮），再点一次取消回到默认视图；切换模块时重置。
- 进入待办模块时清空搜索与选中态（复用现有 `setModule` 行为）；若当前布局是 `table`，自动回落到 `list`。

### 5.2 快速录入

- 内容区顶部常驻单行输入框，占位文案「写下要做的事，回车保存」；输入框**吸顶**，列表滚很长时依然可以直接录入。
- 打开待办模块时输入框自动聚焦（原型不做，生产实现可加）。
- **回车即存**：`trim` 后非空才提交；提交后清空输入框并保持焦点，可连续录入。
- 提交后新待办出现在未完成区顶部（「今天」分段第一条）。
- 创建时间由服务端写入当前北京时间（`Y-m-d H:i:s`），前端不传时间。
- 长度上限 200 字符（前端 `maxlength` + 服务端校验），超出前端截断。
- 右侧「添加」按钮与回车等价；**文字始终显示**（含移动端，不折叠成纯图标）。
- 搜索状态下、或侧栏筛选「已完成」时，快速输入框隐藏；回到默认 / 未完成视图后恢复。

### 5.3 列表布局

- 未完成按创建时间新→旧；按日期分三段：**今天 / 昨天 / 更早**（服务端时区的日期部分）。
- 每行结构：圆形勾选框 → 文字 → 时间 → 悬浮删除按钮；**点击整行（删除按钮除外）即切换完成状态**，不提供行内编辑。
- 时间统一显示完整「YYYY-MM-DD HH:mm」（创建时间），分段标题只负责归组。
- 文字单行不够时换行（`overflow-wrap: anywhere`），行高随内容增长。
- 悬浮行时显示删除按钮；触屏常显。
- 行与行之间用 1px 边框分隔，整段包在一个圆角卡片容器里。

### 5.4 卡片布局（默认）

- 网格卡片：<672px 一列、≥672px 两列、≥1024px 三列（与书签卡片同一套容器断点）。
- **不分段**：所有未完成卡片按创建时间新→旧平铺。
- 卡片结构：头部（勾选框 + 时间 + 悬浮删除）→ 文字（可多行）；**点击整张卡片即切换完成状态**。
- 卡片时间同样显示完整「YYYY-MM-DD HH:mm」。
- 已完成区展开后同样跟随当前布局（列表 / 卡片）。

### 5.5 完成与已完成区

- 点击行 / 卡片（或勾选框）任意位置：`done = true`，服务端记录 `done_at`；该行从未完成区移除，已完成计数 +1。
- 已完成区位于内容区底部，默认**收起**，标题为「已完成 N」（N 为数量），右侧「清除已完成」。
- 点击标题展开 / 收起；展开后按完成时间新→旧排列，已完成项文字划线变灰；行内时间仍展示创建时间（与未完成一致），排序按 `done_at`。
- 在已完成区点击行 / 卡片：`done = false`，`done_at` 置空，回到未完成区对应的日期分段。
- 「清除已完成」：二次确认（沿用现有 `confirmDelete` 弹窗，文案「将删除 N 条已完成待办，此操作无法撤销」），确认后删除全部已完成项，折叠区消失。
- 勾选完成不做 toast（行消失 + 计数变化即为反馈），避免连续勾选时被提示打断。

### 5.6 删除

- 首版**不支持编辑待办文字**：记错了直接删除重写。整行点击 = 切换完成是唯一手势，避免「点文字进编辑」的误操作。
- **单条删除**：行 / 卡片悬浮出现的垃圾桶按钮，点击弹二次确认（「删除这条待办？」+ 待办全文 + 「删除后无法恢复」），确认后删除并 toast「已删除待办」。
- 删除按钮的点击不触发整行切换（按 `data-act` 就近匹配，删除按钮优先）。
- 已完成项同样支持单条删除，删除同样二次确认。

### 5.7 搜索

- 工具栏搜索框，占位「搜索待办...」，实时过滤（输入即生效）。
- 搜索范围：当前筛选范围（默认未完成 + 已完成；侧栏筛选后只在该集合内），匹配待办文字（不区分大小写）。
- 搜索时结果**平铺**：不做日期分段、不折叠已完成；结果上方显示「搜索「关键词」，共 N 条」。
- 已完成项在结果里保持划线样式，时间同样为完整年月日时分。
- 无结果：整块空态「没有匹配「关键词」的待办。」
- 清空搜索（点清除按钮或按 Esc）：恢复分段 + 折叠布局。
- 搜索关键词同步到 URL 的 `search` 参数（与书签 / Skill 一致），不写 `tag` / `page` / `sort`。

### 5.8 空态

| 条件 | 文案 |
| --- | --- |
| 未完成与已完成都为空 | 「还没有待办，在上面写一条吧。」（带 `ListTodo` 图标） |
| 未完成为空但有已完成 | 「未完成的都处理完了，做得好。」+ 底部已完成折叠区 |
| 筛选「未完成」且为空 | 「未完成的都处理完了，做得好。」 |
| 筛选「已完成」且为空 | 「还没有已完成的待办。」 |
| 搜索无结果 | 「没有匹配「关键词」的待办。」 |

### 5.9 视觉与响应式

- 全部颜色使用 `index.css` 的语义 token（`--border` / `--muted` / `--primary` / `--destructive` 等），暗色主题自动适配，禁止硬编码亮色。
- 勾选框为圆形（区别于书签 / 表格的方形复选框），选中态用 `--primary` 填充 + 白色勾。
- 已完成文字划线 + `--muted-foreground`。
- 内容区最大宽度约 56rem 居中，宽屏下不拉满，保持阅读舒适。
- 悬浮显隐沿用 `.onhover-visible`（与全站一致），触屏常显。
- 移动端：内容 padding 与行间距收窄，「添加」按钮保留文字，卡片一列；时间字号降至 11px 仍完整显示。

## 6. 数据模型与接口草案

### 6.1 数据表

```sql
CREATE TABLE IF NOT EXISTS todos (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  text TEXT NOT NULL,
  done INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  done_at TEXT,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_todos_done_created ON todos (done, created_at);
```

- 建表同时写入 `Repository::setupDatabase()`（新库）与 `Repository::migrate()`（老库增量，幂等）。
- 时间统一 `Y-m-d H:i:s`，时区 Asia/Shanghai（`framework/bootstrap.php` 已设置），由服务端生成，前端不传。
- `done` 存储 0/1，出参转换为布尔值。

### 6.2 接口

| 方法与路径 | 入参 | 出参 | 说明 |
| --- | --- | --- | --- |
| `GET /api/todos` | — | `data([{ id, text, done, created_at, done_at }])` | 全量返回，按 `created_at DESC`；前端自行分段 / 搜索 |
| `POST /api/todos` | `{ text }` | `success('已添加待办', { todo })` | `trim` 非空、≤200 字符；`created_at` / `updated_at` 由服务端写 |
| `PATCH /api/todos` | `{ id, done }` | `success('已更新待办', { todo })` | 只切换完成状态：false→true 写 `done_at`，true→false 置空；首版不支持改文字 |
| `POST /api/todos/delete` | `{ id }` | `success('已删除待办')` | id 走请求体（Router 无路径参数） |
| `POST /api/todos/clear-done` | — | `success('已清除已完成待办', { deleted })` | 删除全部 `done = 1`，返回条数 |

- 响应 envelope 与现有接口一致：列表用 `data()` 裸数组，写操作用 `success()`。
- 写操作需要 `X-CSRF-TOKEN`（沿用 CSRF 中间件），登录后可用（不加入认证跳过名单）。
- 错误：`text` 为空 / 超长 / id 不存在返回 400 + `{ success: false, message }`。

### 6.3 前端接入

- `store/api.ts` 增加 `TODOS` 相关 endpoint 常量。
- `store/mainStore.ts` 增加独立 observable：`todos: TodoType[]`，方法 `fetchTodos` / `createTodo` / `updateTodo` / `deleteTodo` / `clearDoneTodos`；写操作成功后局部更新数组（不整表重拉），失败 toast 并回滚。
- `lib/types.ts` 增加 `TodoType`。
- `lib/modules.ts` 增加 `todos` 配置：
  - `label: '待办'`、`noun: '待办'`、`addLabel: '添加'`；
  - `fields: []`（无字段列，视图下拉不渲染「可见字段」区）；
  - `layouts: ['list', 'cards']`（`ModuleConfigType` 新增可选字段，默认三种布局）；
  - `defaultLayout: 'cards'`：布局偏好按模块记忆（切走再回来恢复上次选择），首次进入为卡片；
  - `sorts` 仅保留 `created-desc` 占位（界面不渲染排序菜单）；
  - `routes: { create: null, detail: null }`。
- 列表外壳：新增 `components/Todo/TodoList.tsx`（类似账号库 `AccountVaultList` 的独立外壳），不走通用 `ModuleList`；工具栏 `TodoToolbar`、内容 `TodoContent`、侧栏第二区 `TodoOverview`。

## 7. 验收标准（MVP）

1. 侧栏「待办」位于「书签」下面，图标为 `ListTodo`，徽章显示未完成数，勾选后数字实时减少。
2. 顶部输入框输入文字回车即存，出现在「今天」分段最上方，时间显示当前北京时间。
3. 列表按「今天 / 昨天 / 更早」分段，未完成整体新→旧；空输入回车不产生记录。
4. 勾选后该行移入底部「已完成 N」，计数 +1；在已完成区取消勾选后回到未完成对应分段。
5. 已完成区默认收起，点击展开可见划线灰字；「清除已完成」弹二次确认，确认后清空。
6. 首次进入待办为卡片布局；列表 / 卡片切换正常且按模块记忆；卡片不分段，时间显示完整年月日时分；已完成区跟随当前布局。

## 8. 风险与取舍

| 风险 / 取舍 | 说明 | 处理 |
| --- | --- | --- |
| 无分页 | 待办长期累积后一次性全量返回、整页渲染 | 已完成默认折叠；首版接受，量大再评估分页或虚拟滚动 |
| 删除不可撤销 | 二次确认后仍可能误删 | 确认框展示待办全文；候选 Q2 增加「撤销」 |
| 无标签 / 分组 | 待办变多后只能靠搜索找 | 已确认保持极简；搜索 + 日期分段缓解 |
| 未纳入备份恢复 | 现有四板块备份不含待办 | 已确认不做（T9）；用户接受该取舍，不列入后续默认范围 |
| 时区依赖服务器 | 时间由服务端按 Asia/Shanghai 生成 | 单用户自托管场景可接受；跨时区需求见候选 Q4 |
| 已完成永久保留 | 不自动清理 | 用户手动「清除已完成」；候选 Q5 自动清理 |
